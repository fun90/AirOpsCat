# 本地验收

改动能在控制台或订阅输出中看到效果时，验证通过后由 agent 自行启动本地实例，交给用户验收，不必等用户开口。

## 何时启动

- 启动：改了 `web/templates/`、`web/static/`、`internal/web/` 的页面行为，或改了订阅、docs-info 等用户可直接请求的输出。
- 不启动：纯后端任务、运维脚本、部署与发布、文档、只改测试；用户本轮要求不启动时。

## 步骤

1. **先过验证**：`go vet ./...`、`go test ./...` 通过后再启动。完成：两项通过；失败就修复，不拿坏版本给用户验收。
2. **启动**：在后台运行 `scripts/local-prod.sh 2>&1 | tee ~/.airopscat-local/run.log`。脚本会替换上一轮的本地实例；Go 代码与模板没有热加载，每次改动后都要重启。完成：`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8080/healthz` 返回 `200`。
3. **自查**：用 `curl` 带登录 cookie 请求改动页面，或用浏览器打开，确认改动确实渲染出来。完成：能指出改动出现在哪个具体 URL 的哪个位置。
4. **交给用户**：回复里写明验收 URL（如 `http://127.0.0.1:8080/admin/nodes/<id>/edit`），以及该看哪个位置、生产数据里哪条记录能体现效果。说明实例仍在运行、外发已禁用。

## 约束

- 只用 `scripts/local-prod.sh`，不要自己拼环境变量。它会关闭后台任务和通知，并禁止 SSH 与 DNS 外发。
- 生产快照含真实账户数据：不要把页面内容、订阅链接或授权码贴进回复。
- 脚本因缺少 `AIROPSCAT_DEPLOY_HOST` 或 secret 文件失败时，向用户报告失败原因，不要改用其他数据库凑合验收。
