# 服务器地区、域名绑定与流量自动切换方案

在 [`node-multi-server-deployment-plan.md`](node-multi-server-deployment-plan.md)（逻辑节点 + 部署位，已上线）基础上，把“域名”从节点移到服务器，并按服务器做流量自动切换。

## 1. 目标

1. 服务器有地区、类型（代理服务器 / 落地服务器），域名经 DNS 记录绑定在服务器上，不再维护接入 Host。
2. 节点有地区；部署位按“节点地区 + 节点类型”自动关联同地区同类型的服务器，不再手动添加。
3. 节点、账户订阅定制可选已有域名或新建域名，新建时自动生成 DNS 记录，保存即推送。
4. 服务器流量超阈值时，把它的域名改指向同一节点的其他部署位所在服务器；新周期低于阈值后还原。

## 2. 已确认的决策

| 事项 | 结论 |
|------|------|
| 自动切换粒度 | 服务器级。按“服务器绑定的域名”匹配记录，不按“指向该服务器 IP 的记录”匹配 |
| 部署位 | `node_server` 表保留，由手动添加改为按地区和类型自动同步 |
| 域名归属 | 域名属于服务器（经 DNS 记录的 `server_id`），节点本身没有域名 |
| 一域名一服务器 | 一条 DNS 记录同一时刻只绑一台服务器 |
| 服务器编辑页 | 不再编辑域名；列表页点 IP 弹窗查看服务器信息和绑定域名 |
| 域名粒度 | 每个部署位各自一个域名，同一服务器上的多个节点不共用 |
| 部署位字段 | 移除 `enabled`；`priority`、`exposed` 保留且可在节点表单编辑 |
| 部署位指向域名 | 复用 `node_server.access_host_id`，含义由 `server_host.id` 改为 `domain_dns_record.id` |
| 账户订阅定制 | 只能选一个部署位，域名绑定到该部署位的服务器 |
| 禁用的服务器 | 已有部署位保留，不再为其新生成部署位 |
| 地区来源 | 存量服务器按名称回填；节点取其生效部署位所在服务器的地区（代理节点多为中转，名称里的国家是落地国，不能按名称） |
| 地区与类型 | “美国”不拆地区，用类型区分：名称含 ISP 的是落地服务器，其他美国服务器是代理服务器 |
| 类型匹配 | 代理节点只关联同地区的代理服务器；落地节点关联同地区的落地服务器和代理服务器（代理服务器可兼作落地）。美国2、日本因此保持代理服务器，原有落地节点仍可部署在上面 |
| 部署位扩散 | 接受。自动关联是同地区全部符合条件的服务器，原先只在一台的节点会增加部署位 |
| 域名引用 | 一条 DNS 记录只能被一个部署位或一条账户订阅定制引用 |
| `enabled=0` 存量部署位 | 迁移时静默转为 `exposed=0` 并保留（只部署、不进订阅，作备用），不单独列清单 |
| 切换目标顺序 | 同一节点的其他部署位，按 `priority` 升序 |
| 切换阈值 | 复用 `airopscat.server.monitor.alert.traffic-threshold` |
| 切回时机 | 服务器进入新流量周期且低于阈值 |

## 3. 分期

| 期 | 内容 | 状态 |
|----|------|------|
| 1 | 服务器地区、类型，DNS 记录 `server_id`，IP 详情弹窗 | 代码已完成，未上线（建议与第 2 期一起发） |
| 2 | 节点地区，部署位自动同步，节点域名（选已有 / 新建，保存即推送），订阅 host 取绑定域名 | 待做 |
| 3 | 账户订阅定制域名绑定 | 待做 |
| 4 | 按服务器自动切换与还原；移除 v2.3.7 的节点级切换 | 待做 |

### 3.1 第 1 期（已完成）

- `server.region`、`server.server_type`（0 代理、1 落地，同 `NodeType`）；新建默认代理。
- `domain_dns_record.server_id`；`ServerDomainService`、`GET /api/admin/servers/{id}/domains`（返回 `domains` 与未匹配的 `legacyHosts`）。
- 服务器保存不再写 `server_host` 与 `server.host`；表单“接入 Hosts”换成地区、类型。
- 迁移 `V2026101801__server_region_type_and_domain_binding.sql`：按名称前缀回填服务器地区，按 3.2 迁移的规则回填服务器类型（依赖 `node_server` 已由 `V2026101701` 合并）；按完整域名把旧接入 host 回填为 `server_id`（同一域名被多台服务器使用则跳过）。
- 限制：节点部署位的“接入 Host”下拉仍读 `server_host`，到第 2 期替换；存量服务器地区为空，需人工补填。

### 3.2 第 2 期

**部署位自动同步**

- 触发：节点保存、服务器保存（地区、类型、禁用状态、`external` 变化）、新增 / 删除服务器。
- 规则：服务器地区与节点地区相同、未禁用且 `external=0`（外部服务器无法 SSH 部署），并满足类型匹配的，各生成一个部署位。类型匹配：代理节点只匹配代理服务器；落地节点匹配落地服务器和代理服务器。新部署位 `priority` 取该节点现有最大值加 1，`exposed` 默认 1。已有部署位的 `priority`、`exposed`、域名不被同步改动。
- 不再匹配的部署位：已部署过的标为待删除，否则直接删除。服务器被禁用不算不再匹配，已有部署位保留。
- 节点地区为空时不生成部署位。
- 移除 `node_server.enabled`：节点表单、`NodeServerRequest` / `NodeServerDto`、`NodeServerRepository`、`DeploymentDataLoader`、`SubscriptionService`、`RouteRuleService`、`SingBoxConfigBuilder` 等处原按 `enabled` 过滤的逻辑一并去掉。想让某台服务器不再部署该节点，改服务器或节点的地区 / 类型。落地节点的部署位变多后，出站地址仍取生效部署位（`priority` 最小），新部署位排在已有部署位之后，不改变现有出站。
- 节点表单的部署位行：展示服务器、`priority`、`exposed`、域名，不再有“添加部署位”。

**部署位域名**

- 复用 `access_host_id`，改为指向 `domain_dns_record`；节点表单每行选择域名。
- 选已有记录：必须是 A 记录、未开时段计划、未被其他部署位或账户订阅定制引用，且未绑定其他服务器；选定后写入记录的 `server_id`。
- 新建：填子域名与域名，生成 A 记录指向服务器 IP，`proxied` 默认 `false`，绑定该服务器，保存时单条推送。
- 推送要拿到新记录的 `externalRecordId`：若 Cloudflare 批量接口只返回计数，需扩展返回值取回 id；否则退化为整域推送，会连带推送该域其他待推送修改，实现时确认。
- 部署位不选域名时，订阅用服务器 IP。

**订阅**

- 每个 `exposed=1` 的部署位输出一条订阅，host 取“部署位域名 → 服务器 IP”，替换原 `accessHost → server.host → ip`。`exposed=0` 的部署位只部署，不进订阅，可作备用服务器。
- 废弃“节点绑定 DNS 记录时单条输出”的规则（旧文档 4.3）。

**迁移**

- `server.region`：按名称前缀回填，现有可识别的有：美国、日本、新加坡、德国、英国、越南、香港、马来西亚、韩国、土耳其、墨西哥；“测试”之类无地区词的留空，匹配不上的列清单人工补。
- `server.server_type`：名称含 `ISP` 的置为落地服务器；其余服务器若上面只部署过落地节点，置为落地服务器，否则置为代理服务器。
- `node.region`：取生效部署位（`priority` 最小）所在服务器的地区，不按节点名称。原因：代理节点多是中转，如“德国专线”部署在美国服务器上，名称里的德国是落地国。
- `access_host_id`：由 `server_host.id` 转为 `domain_dns_record.id`，按 host 与 `full_name` 同名且 `server_id` 一致匹配，匹配不上置空并列清单。
- `node.dns_record_id`：按 `full_name` 匹配到生效部署位，写入该部署位的 `access_host_id` 与记录的 `server_id`，随后删除该列。
- `enabled=0` 的存量部署位：迁移时直接置 `exposed=0` 并保留。代价：该节点会在下次部署时部署到这台服务器（原先停用不部署），只是不出现在订阅里。
- 订阅条目数会变化（由每个 DNS 节点 1 条变为每个暴露部署位 1 条），上线前对照检查。

### 3.3 第 3 期（已完成）

- 账户订阅定制（`AccountNodeSubscriptionDomainBinding`）只能选一个部署位；域名可选已有或新建，绑定到该部署位的服务器（`server_id`），保存即推送。
- 所选已有记录若已绑定其他服务器，改绑到当前所选部署位的服务器（不再拒绝）；未被其他部署位 / 定制引用等校验与 3.2 一致，逻辑只放一份。
- 存量定制若关联了多个部署位（`account_node_subscription_placement`），迁移时保留 `priority` 最小的一个，其余列清单核对。
- 存量只有域名、没选部署位的定制，`V2026101803` 为其补一个部署位：记录已绑定的服务器 > 解析 IP 与服务器 IP 一致 > 已部署 > `priority` 最小；并把 A 记录绑定到该服务器。
- 请求改为 `nodeServerId`（必填）+ `domainDnsRecordId` / `newDomainId` + `newSubdomain`；新建记录推送成功（`SYNCED`）前，订阅仍用部署位默认地址。存量被多个引用方共用的记录保持不变，仅在更换域名时按“一条记录一个引用方”校验。

### 3.4 第 4 期（已完成）

**算法（幂等，不单独建切换表）**

对每个“域名引用”R 算一次：R 是“节点 N 的部署位 P 的 `access_host_id`”，或“账户订阅定制绑定的部署位 P（节点 N）”。设 P 所在服务器为 S，记录应指向的服务器为：

- S 使用率低于阈值：S；
- 否则：节点 N 其他部署位中，按 `priority` 升序第一个已部署且服务器使用率低于阈值的，指向其服务器。

与记录当前内容不同才推送。

- 还原无需额外状态：S 进入新周期低于阈值后，下一轮自然算回 S。
- 目标是同一节点的其他部署位，所以目标服务器上一定已部署该节点；`exposed` 不限，备用的 `exposed=0` 部署位也可作目标。
- 只处理 A 记录；记录当前内容不等于 N 任一部署位的服务器 IP 时跳过并记 WARN，避免覆盖无关数据。
- N 的所有部署位都超阈值：记录保持不变，仅首次告警一次。
- 未同步（无 `externalRecordId`）、有待推送创建 / 删除、开了时段计划的记录跳过。
- 推送沿用 `DomainDnsPushService.pushRecordContent`（单条 PATCH 并置 `SYNCED`），不能用整域 push + pull（`DomainDnsPullService.pull` 会用远端覆盖所有本地记录）。
- 落地节点的部署位不参与（出站地址仍取生效部署位）。
- 记录的 `server_id` 始终是归属服务器 S，切换只改记录内容，不改绑定。
- 副作用：被引用的记录内容由系统托管，手动改内容会在下一轮被覆盖。
- 区分“系统切走”和“人工指向别处”：记录上有 `failover_home_content`，切离归属服务器时记下归属服务器的 IP，切回后清空。从未被系统切走、解析又不是归属服务器 IP 的记录视为人工指定，一律跳过并记一次 WARN，避免上线第一轮就把它们改回归属服务器。
- 多个引用方（部署位域名、订阅定制）属于不同节点或服务器时目标不唯一，跳过。

**入口与日志**

- `NodeFailoverService` 改名 `ServerFailoverService`，仍由 `TrafficStatsTask` 采集后调用。
- 日志继续写 `SystemLog`，分类 `NODE_FAILOVER` 改为 `SERVER_FAILOVER`（`V2026101803` 迁移历史日志），`detail` 记录节点、归属 / 目标服务器、原 / 新内容、使用率、`reason`（`THRESHOLD` / `RESET`）、`success`。
- 通用系统日志页、`system-log-cleanup` 任务、保留天数配置保持不变。

**移除 v2.3.7 的节点级逻辑**

- `node.failover_enabled`、`node.active_node_server_id`，节点表单“自动切换”开关与部署位“解析中 / 切换”按钮。
- `POST /api/admin/nodes/{id}/failover/switch` 与 `NodeFailoverSwitchRequest`；手动切换暂不保留。
- 订阅按 `active_node_server_id` 取快照的分支。
- 相关 DTO 同步调整 `JsonReflectionConfiguration`。

## 5. 上线前核对

- 部署位扩散：按本地库旧字段估算，节点“美国”（id 34）原只在美国-主控，上线后会部署到美国、美国2、美国-主控；美国的落地节点（如“美国2落地”）也会增加到其他美国代理服务器。上线前在迁移库副本上跑部署位同步，核对新增部署位清单后再发。
- 本地库的 `node_server` 为空，以上基于旧字段 `node.server_id`，生产库需复核。
- 域名解析与归属服务器不一致：本地库有 5 个部署位的域名（`us3` / `bojue` / `uk` / `hk` / `de`）解析到的不是其部署位服务器的 IP，且归属服务器使用率远低于阈值，不像是超阈值切换的残余，推测为人工指向，未向你核实。上线后这些记录被视为人工指定、不会被自动切换；若要纳入自动切换，先在域名页把内容改为归属服务器 IP。
- 账户订阅定制：`V2026101803` 执行后运行脚本末尾的核对查询（无部署位、服务器不一致、非 A 记录、共用记录）。存量定制从“可选多个部署位、域名任意”收紧为“一个部署位、域名绑定其服务器”，保存时可能因域名已绑定其他服务器被拒绝，需重新选择域名。
- 发布说明要列出的行为变化：部署位域名从 host 改为 DNS 记录；订阅条目由 1 条变为每个暴露部署位 1 条；账户定制被裁剪为单部署位；自动切换从节点级改为服务器级，手动切换入口移除。
