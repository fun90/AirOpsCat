2026-10-21 升级回滚演练（用户授权，仅指定测试服务器）：本地构建 `0245889`（schema 6）与当前 `HEAD`（schema 7）的 Linux amd64 二进制，上传后 SHA-256 校验通过。在 `/tmp` 私有目录内用 `systemd-run` 临时单元运行（`ProtectSystem=strict`、只写状态目录、`127.0.0.1:18090`、任务和通知关闭、随机密钥与口令）。结果：旧版首装健康，user_version=6；写入标签和金额后，停服并备份 DB/WAL/SHM 文件组；新版升级健康，user_version=7，数据保留，VmRSS 24,048 KB；新版写入后停服，手动整组恢复备份并启动旧版，回到 6，备份前写入的数据保留、升级后写入消失；再次升级到 7 成功。这一步是"升级成功后的手动恢复"，不是迁移失败。结束后临时单元不存在、端口关闭、目录删除，既有 `sing-box`、`airopscat`、`airopscat-guard-agent` 仍 active。未覆盖 GitHub Release 下载、`install.sh` 自身的标准路径写入和独立 `airopscat` 用户。

2026-10-21 迁移失败注入（同一测试机、同样隔离方式，`127.0.0.1:18091`、`Restart=no`）：故障版为当前 `HEAD` 加一个只存在于临时 worktree 的必然失败迁移 `0008`（先建表再查询不存在的表），未提交到仓库。旧版首装 user_version=6，写入数据后停服备份文件组。故障版启动后进程退出码 1，健康检查不通过，日志含"执行 0008_drill_fail.sql 失败"。此时 user_version=7：`0007` 已单独提交，`0008` 整个事务回滚，未留下半建的表。备份前数据保留。整组恢复备份后旧版健康，回到 6。结论：迁移按文件逐个提交，多文件升级失败可能停在中间版本，回滚必须整组恢复停服前备份，不能只换回旧二进制。`install.sh` 的自动回滚已由 `--self-test` 用 mock 覆盖，真实 systemd 下的自动回滚仍未执行。演练后临时单元、端口、目录已清理，既有三个服务仍 active。

## 运行边界

- 自动 DNS 当前按 vnstat 自然月统计，不支持供应商非自然月计费。未知远端操作保留待核查，不盲目重发。
- Guard 为单实例内存聚合；进程重启会重新累计。超限只拒绝新连接，不踢存量连接。
- 维护批次需要保持页面打开，各步骤独立服务器锁；断连时需核查实际服务器状态。
- 维护页面曾误发一次 `02-swap.sh` 测试请求后中断；已核查原 swap 文件未改写、无临时目录、sing-box active；该过程不视为批量初始化验收。
