## ADDED Requirements

### Requirement: 系统 SHALL 按配置记录请求日志
系统 SHALL 提供可配置的请求路径记录能力，并默认记录 `/api/open/docs-info/*` 与 `/subscribe/*` 下的请求。命中记录范围的请求 MUST 被持久化为系统请求日志，且日志 MUST 至少包含客户端 IP。

#### Scenario: 默认路径请求被记录
- **WHEN** 客户端访问 `/api/open/docs-info/latest` 或 `/subscribe/account-token`
- **THEN** 系统写入一条请求日志
- **AND** 日志包含访问时间、请求方法、请求路径、客户端 IP、状态码和耗时

#### Scenario: 非配置路径请求不被记录
- **WHEN** 客户端访问未配置记录的路径
- **THEN** 系统不写入系统请求日志

#### Scenario: 管理员调整记录路径配置
- **WHEN** 管理员修改请求日志记录路径配置
- **THEN** 系统按新的路径范围判断后续请求是否需要记录

### Requirement: 请求日志 SHALL 保留排查字段且避免记录敏感正文
系统 SHALL 为每条请求日志保存用于排查的结构化字段，包括访问时间、请求方法、请求路径、查询参数、客户端 IP、状态码、耗时、User-Agent 与 Referer。系统 MUST NOT 记录请求体、响应体或订阅内容正文。

#### Scenario: 日志字段完整可用于排查
- **WHEN** 命中记录范围的请求完成响应
- **THEN** 系统保存该请求的访问时间、请求方法、请求路径、查询参数、客户端 IP、状态码、耗时、User-Agent 与 Referer

#### Scenario: 请求正文不进入日志
- **WHEN** 命中记录范围的请求携带请求体或响应体
- **THEN** 系统请求日志不保存请求体、响应体或订阅配置正文

### Requirement: 管理员 SHALL 搜索和分页浏览请求日志
系统 SHALL 提供后台请求日志列表，管理员 MUST 能够按访问时间段、请求路径、客户端 IP 搜索日志，并分页浏览结果。请求路径与客户端 IP 条件 MUST 使用模糊匹配。

#### Scenario: 按访问时间段过滤日志
- **WHEN** 管理员输入开始时间和结束时间查询请求日志
- **THEN** 系统仅返回访问时间落在该区间内的日志

#### Scenario: 按请求路径模糊搜索日志
- **WHEN** 管理员使用请求路径关键字查询请求日志
- **THEN** 系统返回请求路径包含该关键字的日志

#### Scenario: 按客户端 IP 模糊搜索日志
- **WHEN** 管理员使用客户端 IP 片段查询请求日志
- **THEN** 系统返回客户端 IP 包含该片段的日志

#### Scenario: 日志列表分页展示
- **WHEN** 管理员查看请求日志列表
- **THEN** 系统按访问时间倒序返回分页结果
- **AND** 返回总数、总页数、当前页和每页数量

### Requirement: 系统 SHALL 提供请求日志统计图表
系统 SHALL 在请求日志管理页面提供 apexcharts 统计图表。统计图表 MUST 包含按请求路径统计的图表，并 SHOULD 同时提供访问趋势与客户端 IP 维度统计以辅助排查。

#### Scenario: 按请求路径统计图展示
- **WHEN** 管理员打开请求日志管理页面
- **THEN** 页面使用 apexcharts 展示按请求路径聚合的请求数量图表

#### Scenario: 图表统计范围跟随筛选条件
- **WHEN** 管理员设置访问时间段、请求路径或客户端 IP 搜索条件
- **THEN** 图表统计结果与日志列表使用相同的过滤范围

#### Scenario: 趋势与 IP 统计辅助观察
- **WHEN** 管理员查看请求日志统计区域
- **THEN** 页面展示按时间聚合的访问趋势或客户端 IP Top N 统计中的至少一种额外图表

### Requirement: 系统 SHALL 定时清理过期请求日志
系统 SHALL 定时清理系统请求日志，仅保留近 30 天的记录。清理逻辑 MUST 基于日志访问时间判断是否过期。

#### Scenario: 清理 30 天以前日志
- **WHEN** 请求日志清理任务执行
- **THEN** 系统删除访问时间早于当前时间 30 天的请求日志
- **AND** 保留近 30 天内的请求日志

#### Scenario: 清理任务避免并发执行
- **WHEN** 上一次请求日志清理任务仍在运行
- **THEN** 系统跳过新的并发清理执行
