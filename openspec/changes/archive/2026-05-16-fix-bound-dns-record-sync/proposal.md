## Why

账户节点订阅域名绑定会通过外键引用 `domain_dns_record`。当前 DNS 拉取同步采用“删除本域名全部 DNS 记录后重新插入”的方式，一旦某条 DNS 记录已经绑定到账户节点订阅域名，同步时删除父表记录会触发数据库外键约束错误，导致 DNS 记录同步失败。

同类风险也存在于手动删除 DNS 记录、切换 DNS 服务商绑定和解绑域名 DNS 的流程中：这些操作可能删除仍被订阅绑定引用的 DNS 记录，造成异常或订阅配置失效。

## What Changes

- DNS 拉取同步从全量删除重建改为按远端记录标识增量对齐，尽量保留本地 DNS 记录 ID。
- 本地存在但远端不存在的 DNS 记录，如果未被绑定则删除；如果已被绑定则保留并标记为 `PENDING_DELETE`。
- 手动删除 DNS 记录时，如果记录已被账户节点订阅域名绑定引用，则拒绝删除并提示先解绑。
- 切换 DNS 服务商绑定或解绑域名 DNS 前，如果域名下存在已绑定 DNS 记录，则拒绝操作并提示先解绑。

## Capabilities

### Modified Capabilities

- `account-node-subscription-domain-binding`: 补充已绑定 DNS 记录在 DNS 同步、删除、解绑和切换服务商时的保护规则。

## Impact

- **后端**：调整 DNS 拉取同步策略，新增绑定引用检查，更新 DNS 记录删除与域名 DNS 绑定变更流程。
- **数据库**：不新增表结构；复用既有外键约束和绑定关系。
- **前端/API**：删除或解绑时可能返回更明确的业务错误提示，要求管理员先解除订阅域名绑定。
- **测试验证**：至少执行编译验证，并建议在真实数据上验证已绑定记录同步、删除和解绑提示。
