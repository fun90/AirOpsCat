## Why

当前账户通过标签获得可用节点后，订阅中同一节点只能展示节点自身的默认访问地址，无法为不同账户分配各自对应的 DNS 完整域名。代理服务商在同一节点承载多个账户时，需要按账户精细控制订阅里的连接地址，同时不影响节点部署、标签授权和节点用户列表生成。

## What Changes

- 新增账户-节点订阅域名绑定能力，允许管理员为某个账户在某个节点上配置一个来自 `domain_dns_record.full_name` 的订阅展示域名。
- 同一账户在同一节点上最多只能绑定一个 DNS 记录；同一账户可以为多个节点分别绑定 DNS 完整域名；同一节点可以被多个账户分别绑定不同 DNS 完整域名。
- 订阅生成时仍先按现有“节点标签 -> 账户标签”规则确定账户可用节点。
- 绑定管理选择节点时只允许选择该账户通过标签授权得到的节点，并默认加载前 20 条可选节点。
- 当账户订阅包含某个节点且存在账户-节点域名绑定时，订阅中的该节点连接地址优先使用绑定 DNS 记录的 `full_name`。
- 当绑定不存在、禁用或关联 DNS 记录不可用或 `full_name` 为空时，订阅继续使用现有节点地址解析逻辑。
- 绑定只影响订阅中展示给该账户的连接地址，不影响节点部署、不影响节点用户列表、不触发节点重新部署。

## Capabilities

### New Capabilities
- `account-node-subscription-domain-binding`: 定义账户在指定节点上的订阅域名绑定、唯一性约束、管理接口与订阅生成优先级。

### Modified Capabilities
- 无。

## Impact

- 数据模型：新增账户-节点-DNS 记录绑定实体与表，建议建立 `account_id + node_id` 唯一约束。
- 管理接口：新增绑定的查询、创建或更新、启用或禁用、删除能力，便于账户详情或节点详情页面管理。
- 前端页面：账户或节点相关管理界面需要提供绑定 DNS 完整域名的查看与编辑入口，复用现有账户、节点和 DNS 记录远程搜索组件。
- 订阅生成：`SubscriptionService` 在构造账户可用节点 DTO 时需要按账户和节点查询绑定，并覆盖订阅输出中的节点连接地址。
- 部署链路：`DeploymentDataLoader`、节点部署快照、节点用户列表和远端配置生成不应读取该绑定。
- 原生镜像：新增 DTO 或请求/响应类型需要按项目约定注册到 `JsonReflectionConfiguration`。
