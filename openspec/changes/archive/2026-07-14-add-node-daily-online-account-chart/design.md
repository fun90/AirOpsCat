## Context

节点在线状态当前由 `AccountOnlineIpService` 基于 sing-box 在线状态快照或连接列表刷新到 `account_online_ip`，节点列表通过 `NodeService.fillOnlineConnectionCounts` 展示当前在线连接数量，并通过 `/api/admin/nodes/{id}/online-accounts` 查看当前在线详情。系统监控页面使用 `ServerMonitorController`、`ServerMonitorStatsService`、ApexCharts 和 Qute 模板展示趋势图。

`account_online_ip` 是当前在线窗口和短期历史记录，不适合直接作为每日趋势数据源：默认清理配置会删除较早记录，且同一账号可能存在多条连接记录。为满足管理员判断扩缩节点的目标，需要把“当前在线窗口内的节点在线账号数”周期性沉淀为按日统计。

## Goals / Non-Goals

**Goals:**

- 提供节点每日在线账户数量趋势，帮助管理员快速判断节点使用高峰、低利用率和增长趋势。
- 在节点列表页增加入口，从单个节点直接进入趋势页面。
- 复用现有在线状态记录作为统计来源，不新增节点侧脚本或外部采集链路。
- 图表交互和视觉风格参考系统监控页面，使用现有 Tabler、Qute、petite-vue 和 ApexCharts 模式。
- 统计“账号数量”时按 `accountNo` 去重，避免同一账号多连接导致容量判断失真。

**Non-Goals:**

- 不实现自动扩容、自动缩容或容量预测决策。
- 不重做当前在线连接详情弹窗。
- 不改变在线状态刷新链路、在线窗口判定配置或节点部署流程。
- 不统计落地节点与代理节点之间的转发链路关系，只按在线记录归属的逻辑节点统计。

## Decisions

1. 新增日统计持久化表，而不是直接查询 `account_online_ip` 历史。

   - 方案：新增 `node_online_account_daily_stats`，按 `node_id + stat_date` 唯一，保存每日峰值在线账号数、最近采样在线账号数、累计去重在线账号数、采样次数和最后采样时间。
   - 理由：现有在线记录会被清理，无法保证历史天级趋势；日统计表数据量小，查询图表稳定。
   - 备选：直接延长 `account_online_ip` 保留时间。该方案会扩大在线明细表数据量，并且仍需要复杂去重和跨天统计。

2. 统计来源使用当前有效在线记录，按账号去重。

   - 方案：定时任务读取当前有效在线窗口内 `node_id` 非空的在线记录，按节点聚合 `distinct accountNo`，写入当天统计。
   - 理由：管理员关心节点承载了多少账号，而不是连接条数；现有连接详情仍保留连接维度。
   - 备选：按连接数统计。该方案容易被多客户端或多连接账号放大，不适合作为扩缩节点依据。

3. API 拆分为摘要和图表数据，页面模式参考系统监控。

   - 方案：新增节点在线统计控制器，例如 `/api/admin/node-online-account-stats/{nodeId}/summary` 和 `/api/admin/node-online-account-stats/{nodeId}/charts?days=30`。
   - 理由：和系统监控的 `summary`、`charts` 契约相似，前端实现和错误处理可复用思路；接口职责清楚。
   - 备选：挂在 `NodeController` 下。该方案路径更短，但会让节点 CRUD 控制器继续膨胀。

4. 页面作为控制台独立页面注册，但不在侧边菜单展示。

   - 方案：新增 `/console/vpn/node-online-account-stats?nodeId=...` 页面，注册到 `ConsolePageRegistry`，`showInMenu=false`，从节点列表下拉菜单或在线连接列进入。
   - 理由：这是节点管理的上下文详情页，入口应来自节点列表；避免侧边菜单增加低频页面。
   - 备选：在节点列表内弹窗展示图表。该方案空间受限，不利于查看 30/60/90 天趋势和摘要。

5. 图表展示每日活跃账号和峰值在线账号。

   - 方案：主图使用面积折线图展示每日去重在线账号数和每日峰值在线账号数；摘要卡展示今日当前值、今日峰值、周期峰值和周期平均值。
   - 理由：每日去重账号反映使用覆盖面，峰值在线账号反映容量压力，二者组合更适合扩缩节点判断。
   - 备选：只展示单条每日账号数。该方案更简单，但容量判断信息不足。

## Risks / Trade-offs

- 日统计依赖定时任务运行 → 在应用停机期间会缺少采样；页面应明确空数据状态，统计服务可在读取时为当天执行一次轻量补采样。
- 采样频率影响峰值精度 → 复用在线刷新或任务配置的分钟级频率，并在摘要中展示最后采样时间。
- 同一账号多连接被去重后低于连接压力 → 图表聚焦账号数量；当前在线连接详情仍用于排查连接维度压力。
- 未映射到逻辑节点的在线记录无法进入节点趋势 → 保持现有节点字段允许为空的行为，趋势页只统计可归属节点的数据。
- 新增 DTO 在原生镜像中遗漏登记 → 实施任务中明确检查并更新 `JsonReflectionConfiguration`。

## Migration Plan

- 新增日统计实体、仓库和数据库迁移脚本，创建 `node_online_account_daily_stats` 表及 `node_id + stat_date` 唯一索引。
- 部署后由新定时任务开始写入当天统计；历史日期无数据时页面展示空状态，不回填不可恢复的明细。
- 回滚时可保留统计表，不影响现有在线状态和节点列表；移除页面入口和任务后统计表停止更新。
