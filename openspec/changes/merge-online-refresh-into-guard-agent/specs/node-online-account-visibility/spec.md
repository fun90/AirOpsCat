## MODIFIED Requirements

### Requirement: 管理页在线详情必须复用在线状态记录
系统 SHALL 让当前管理页中的账号在线详情、节点在线详情和服务器在线账号详情复用在线状态刷新写入的在线记录，不为这些页面引入独立的数据源，并保持账户、节点、服务器三个维度的在线查询能力。

#### Scenario: 管理员查看账号在线详情
- **WHEN** 管理员打开账号在线连接详情
- **THEN** 系统从当前有效在线记录返回连接 ID、客户端 IP、服务器 IP、节点信息、最后在线时间和在线时长

#### Scenario: 管理员查看节点在线详情
- **WHEN** 管理员打开节点在线连接详情
- **THEN** 系统从当前有效在线记录返回账号、连接 ID、客户端 IP、服务器 IP、最后在线时间和在线时长

#### Scenario: 管理员查看服务器在线账号详情
- **WHEN** 管理员打开服务器在线账号详情
- **THEN** 系统从当前有效在线记录返回账号、客户端 IP、最后在线时间和在线时长

#### Scenario: 在线查询维度保持兼容
- **WHEN** 管理员分别按账户、节点或服务器查询当前在线连接
- **THEN** 系统仍返回对应维度当前有效在线窗口内的在线记录
- **AND** 查询能力不因在线刷新来源改为 guard agent 上报而减少

### Requirement: 在线状态刷新必须通过 Clash API 主动采集
系统 SHALL 在刷新账号在线状态时优先使用节点 guard agent 通过 `guard-sync` 上报的在线连接明细，并使用连接中的账号、客户端 IP、连接 ID、节点标识和连接开始时间维护在线记录。

#### Scenario: guard 在线连接明细可用
- **WHEN** 节点 guard agent 通过 `guard-sync` 上报当前在线连接明细
- **THEN** 系统使用该明细刷新账号在线记录
- **AND** 系统不再为该节点的常规在线刷新额外 SSH 读取完整 Clash API 连接列表

#### Scenario: guard 在线连接明细不可用
- **WHEN** 节点未部署 guard agent、上报缺少在线连接明细或上报已过期
- **THEN** 系统暴露该节点在线刷新链路不可用状态
- **AND** 系统可以在显式启用回退配置时使用中心 Clash API 采集刷新该节点在线记录

#### Scenario: guard 连接映射到节点
- **WHEN** guard 在线连接明细中包含可映射到 AirOpsCat 节点的节点标识
- **THEN** 系统在在线记录中保存对应节点 ID 和节点标识

#### Scenario: guard 连接无法映射到节点
- **WHEN** guard 在线连接明细中缺少节点标识或无法映射到 AirOpsCat 节点
- **THEN** 系统仍保存服务器维度在线记录
- **AND** 节点字段允许为空
